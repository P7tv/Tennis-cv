## 1. Coordinate Transformation & Camera Normalization

ระบบ calibrate **ต่อคลิป** (per-clip, self-contained) — ไม่ต้องรู้ spec
กล้อง รองรับคลิปที่มุมไม่เท่ากันโดยดีไซน์:

| ขั้น | วิธี | แก้ปัญหา |
|---|---|---|
| Ready-phase detection | เฟรม motion ต่ำในครึ่งแรกของคลิป | เป็น reference ทุกขั้นถัดไป |
| px→cm scale | `body_height_cm ÷ ระยะ ankle→head (norm)` + **trunk length เป็น per-frame anchor** (ลำตัวไม่ยืดหดตามท่า) | ระยะกล้อง/zoom ต่างกัน, ผู้เล่นวิ่งเข้า-ออก |
| Roll correction | median จาก (ก) เส้นข้อเท้าควรนอน (ข) แกน hip→shoulder ควรตั้ง ณ ready → หมุน landmark กลับ | กล้องเอียง |
| Rotation zero-reference | 0° ของ shoulder/hip rotation = ค่า ณ ท่า ready ของคลิปนั้น ⚠️ **สมมติฐาน: ท่า ready ไหล่ขนาน baseline** | กล้องเยื้องกลาง (yaw) + ท่ายืนรายบุคคล |
| Deviation envelope | world-z asymmetry ของไหล่ ณ ready → <15° ok / 15–30° degraded (cap confidence) / >30° → VQ `side_view` ⚠️ ตัวเลข TBC | คุมคุณภาพมุมกล้อง |

- **แหล่งของ `body_height_cm` (C1):** ⚠️ ต้องยืนยัน — ข้อเสนอ: Loeuf ส่ง
  player height มากับ request (Phase 2 doc ระบุ "send from GAS" อยู่แล้ว);
  ไม่มี → ใช้ 170cm + ทุก cm field ติด `low_confidence`
- **Auto-height จาก court calibration** (`court_calibration.py`,
  `auto_height_from_court` config flag, default `False`): ทดลองแล้วบน
  คลิปจริง 2 อัน (2026-07-09) — สูตร geometry (homography + weak-perspective)
  ถูกต้องและเทสผ่านหมด แต่ **การหาเส้นคอร์ทอัตโนมัติ (perception layer)
  ยังไม่เสถียรพอสำหรับ production**: focal length ที่ประมาณได้แกว่งเกือบ
  2 เท่าข้ามเฟรมในคลิปเดียวกัน (กล้องไม่ขยับ) เพราะเส้นสนาม/รั้ว/แสง
  กลางคืนทำให้ classify เส้น baseline/service-line/sideline ผิดบ่อย
  → **สถานะ: experimental, opt-in เท่านั้น** ไม่แนะนำให้พึ่งเป็นค่าเดียว
  สำหรับ production จนกว่าจะ tune กับข้อมูล labeled จริงเพิ่ม
- fps normalization: input < 60fps → linear resample เป็น 60fps
  (`velocity_normalized: true`) — KN fields จากต้นทาง 30fps ติด
  `low_confidence` เพราะ velocity fidelity จำกัดที่ fps จริง

### 1.1 Device / Lens / Color normalization (มือถือต่างรุ่น)

| ความต่าง | การจัดการ |
|---|---|
| White balance / โทนสีต่างยี่ห้อ | gray-world WB ต่อเฟรมก่อนเข้าโมเดล (`image_norm.py`) — จำเป็นกับ ball detector (สีลูก) มากกว่า pose |
| Exposure / แสง | ดึง mean luma เข้า target + CLAHE เมื่อภาพมืด — VQ stats วัดจากเฟรมดิบเสมอ |
| FOV / focal length / zoom | ดูดซับสมบูรณ์โดย body-relative scale (ไม่มีสมมติฐาน pixel สัมบูรณ์) |
| Lens distortion | ⚠️ ไม่ทำ per-device undistortion (ต้องมี calibration target ต่อรุ่น — ไม่ realistic) → กติกาถ่าย "เลนส์หลัก 1x + ผู้เล่นกลางเฟรม" + VQ flag `player_near_edge` (enum เสนอเพิ่ม) เมื่อผู้เล่นชิดขอบ >25% ของคลิป |
| Rolling shutter | ยอมรับเป็น limitation (กระทบเฉพาะเฟรมสวิงเร็วสุด ระดับ sub-pixel ถึงไม่กี่ px) |
| Ball detector (อนาคต) | ความต่างสีที่เหลือ → จัดการด้วย **color augmentation ตอน train** (hue/saturation jitter) ไม่ใช่ runtime |

## 2. Landmark Definition

- Pose model: **MediaPipe BlazePose** (`pose_model_version` ใน MT0) — 33 keypoints
- นิยามจุดประกอบ: `shoulder_mid = (kp11+kp12)/2` · `hip_mid = (kp23+kp24)/2` ·
  `torso_center = (shoulder_mid+hip_mid)/2` (ใช้ใน C17, C32)
- **CoM**: สูตร segment weighting ตาม schema doc (trunk 0.50, upper arm
  0.03×2, forearm 0.02×2, thigh 0.10×2, shank 0.10×2)
- ⚠️ Deviation จาก spec ที่ flag ตามกติกา "flag explicitly":
  - C31 wrist angle: ไม่มี racket detector → ใช้ hand **index keypoint**
    (kp19/20) แทนปลาย racket
  - KN7 racket_head_speed: fallback จาก wrist path (ตามที่ doc อนุญาต)
  - C39 pronation / C40 racket_face: `null` (requires side view / racket)

## 3. Keyframe Detection Proxies (B1–B5)

| Keyframe | Proxy ที่ใช้ | หมายเหตุ |
|---|---|---|
| B1 unit_turn | onset ของ torso rotation proxy (shoulder width หดในภาพ) ≥30% ของ peak | |
| B2 backswing_peak | wrist ห่างลำตัว (x) มากสุดก่อน impact | |
| B3 impact | **peak wrist speed + sub-frame parabolic interpolation** | ได้ timestamp ละเอียดกว่า frame spacing; มี ball detector → fuse กับจุดลูกเปลี่ยนทิศ |
| B4 follow_through_peak | wrist ไกลจาก hip center สุด ภายใน 1s หลัง impact | |
| B5 ready_restored | ท่าใกล้ ready reference ต่อเนื่อง ≥3 เฟรม | detect ไม่ได้ = ข้อมูล ไม่ใช่ error |

## 4. Back-view Reliability ต่อ field

ตาม camera_dep ใน schema doc — implement แล้วใน pipeline:
- `Reliable` (C1–C28, KN1–KN4): visibility ตาม landmark จริง
- `Limited` (C29–C38, KN6, C41 → block `depth_estimated`): **cap ที่
  `low_confidence` เสมอ** เพราะพึ่ง depth จาก monocular
- `Requires side view` (C39, C40): ส่ง `null` + `not_detectable`
- Matrix ฉบับ evidence-based จะออกหลัง benchmark 300 คลิป
  (accuracy แยกตาม camera deviation — ดู `run_benchmark.py`)
